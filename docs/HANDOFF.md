# HANDOFF

## 已谈定

- 2026-10-14 · 用户 · 目标：一个物理 COM 口拆成多个虚拟 COM 口，让协议模拟器和原来的串口助手同时用同一个物理口。急用。
- 2026-10-14 · 用户 · 技术路线：纯 Rust + Slint 图形界面；虚拟口由 com0com 驱动提供，转发逻辑由本程序自己做，不依赖 hub4com。排除：自写 Rust 驱动（要测试签名模式、周期长）、TCP 方案（串口助手不支持）。
- 2026-10-14 · 用户 · 功能模型是"分组"：一个分组 = 一个物理口 + 用户设的波特率等参数 + 拆成的若干虚拟口；分组配置可保存、可建多个。排除：自动接管全部物理口（用户："自动监管这个要求确实离谱了"）、波特率跟随虚拟口上的应用设置（改为用户在分组里设）。
- 2026-10-14 · 用户 · 功能：开机自启；关闭窗口可选退出或最小化到托盘；监控的数据存进 SQLite；其余逻辑由 AI 补全。
- 2026-10-14 · 用户 · 新分组默认波特率 2400。
- 2026-10-14 · 用户 · 界面：v1 界面"太丑"，改用样稿 B 方向（分组做顶部标签页、参数在左栏、状态在底部状态条），但默认白色（设置里可切深色）；字符输出区默认隐藏，点"显示数据"才向右展开；默认小窗口（约 360×470），"只是个基础的虚拟串口工具"。样稿见 `docs/ui-mockup.html`。排除：A 浅色工作台、C 拓扑卡片。
- 2026-10-14 · 用户 · 界面细化：最终采用工业上位机风格（样稿 v3）；窗口要能拉伸，当前大小（收起 300×334、展开 780×334）作为最小值；"转发到虚拟口"框要有滚动条，口多时能选到下面的。AI 补充（已告知用户）：拉高时多出的高度给虚拟口框，窗口大小记住。
- 2026-10-14 · 用户 · 本程序用的 com0com B 端（CNCBn）不能出现在其他串口软件的列表里：用 com0com 的 HiddenMode=yes 隐藏 B 端，程序新建虚拟口对时自动隐藏。
- 2026-10-14 · AI 补全（已告知用户） · 窗口内新建/删除 com0com 虚拟口对（每次一个 UAC）；一个虚拟口只能属于一个分组；不同物理口的分组可同时运行；上次退出时在运行的分组启动后自动恢复，物理口不在就每 3 秒重试；关闭窗口第一次询问并可记住；单实例，重复启动唤出已有窗口；SQLite 默认保留 30 天；不转发 DTR/RTS 等控制线。
