# serial-split 变更记录

## 2026-10-14 隐藏本程序使用的虚拟 B 端并修正设置列表对齐

**起因**：用户的普通串口助手下拉里出现了 `CNCB0~CNCB4`；用户要求“本程序用的 com0com B 端（CNCBn）不能出现在其他串口软件的列表里”。设置窗快照中第 4 行的第二、三列也比其他行偏右。

**根因**：此前把默认名字 `CNCBn` 当作不会被枚举的保证；实际上 com0com 将两端登记到 SERIALCOMM，普通串口软件仍能枚举 B 端。隐藏后 B 端可能从 SERIALCOMM 消失，但 Parameters 会留下含 HiddenMode、没有 PortName 的子键，检测不能依赖 B 端仍在枚举表中。列表各行又按各自文字分配列宽，造成错位。

**改成**：新建时自动设置 B 端 `HiddenMode=yes`；检测支持隐藏后的注册表形态及 HiddenMode 字符串／DWORD。存在未隐藏 B 端时显示“隐藏本程序端”，一次提权批量处理后重新检测，全部隐藏后按钮消失。设置列表统一列宽，快照保留一对未隐藏端以展示按钮。

**没选的路**：不再依靠 `CNCBn` 名字断言端口不会被枚举；使用驱动提供的 HiddenMode。

**影响**：已有口对需要执行隐藏操作，原有分组配置和录制格式不变；驱动及外部枚举器决定最终隐藏效果。本轮没有实际执行 setupc，UAC 次数和驱动效果仍待实机确认。

## 2026-10-14 改为紧凑的工业上位机界面

**起因**：用户说 v1 界面“太丑”，后续样稿仍“还是不够紧凑，工业上位机风格”，并强调“只是个基础的虚拟串口工具，我要小一点”。

**根因**：原界面控件过高、过圆，固定展示数据区占用空间，与基础串口小工具的用途不合。

**改成**：分组置于顶部标签页，参数位于左侧、状态位于底部；默认 300×334 小窗口，数据区默认收起，按需向右展开至 780×334。统一为细边框、紧凑控件、方角按钮和状态灯，增加浅色／深色主题、HEX／文本显示，保存主题与展开状态。转发、录制、检测、托盘等行为延续 v1。

**没选的路**：排除浅色工作台、拓扑卡片方向；不继续使用高大圆润的 Fluent 控件。采用经三轮确认的工业上位机样稿。

**影响**：旧 INI 配置继续可读，缺少新增键时默认浅色、数据区收起。

## 2026-10-14 首次交付：多个软件共用一个物理串口

**起因**：用户急需“让协议模拟器和串口助手同时用同一个物理口”，同时“把数据录进 SQLite”，并要求多个分组配置、托盘与开机自启。

**改成**：Windows 桌面工具把物理口数据原样分发到分组中的多个虚拟 A 端，各软件发送的数据汇入物理口；支持保存配置、独占检查、故障重试与启动恢复，按需录制原始字节到可并行查询的 SQLite，提供托盘、关闭动作和自启。

**没选的路**：不自写 Rust 串口驱动（需要测试签名、周期长），不使用 TCP 替代（现有串口助手不支持），不自动接管全部物理口（用户：“自动监管这个要求确实离谱了”），不跟随虚拟口应用修改物理口波特率；由用户在分组中明确设置。

**影响**：虚拟口依赖 com0com，A 端供外部软件使用、B 端由本程序使用；不转发控制线，也不依赖 hub4com。
